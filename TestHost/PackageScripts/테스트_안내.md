# DTCctv 테스트 패키지

UE 5.3 Development 패키지입니다. 운영 프로젝트에 설치하는 플러그인과 별개의 시험 도구입니다.

## 로컬 창에서 보기

Windows는 `보기.bat`, Linux는 `./view.sh`를 실행합니다. Linux는 GPU 드라이버·Vulkan과 디스플레이가 필요합니다. 실행 권한이 없으면 패키지를 소유한 계정에서 `chmod +x view.sh pixelstreaming.sh check-nullrhi.sh DTCctvTestHost/Binaries/Linux/DTCctvTestHost`를 적용합니다.

1. RTSP 주소와 선택적인 서브 주소·사용자 이름·비밀번호를 입력하고 **추가**합니다. 주소는 최대16개입니다.
2. **보기**를 누르면 입력한 전체 목록을 시간 제한 없이 재생합니다. 영상·상태·코덱·해상도·FPS·디코더·재연결·오류를 확인하고 1열/2열/4열을 선택하거나 창 크기를 바꿀 수 있습니다.
3. **중지**로 종료합니다. 보기 중에는 주소 편집과 시작이 비활성입니다. 중지 뒤 주소를 고치고 다시 보기를 누릅니다.

**시작**은 지정한 시간 동안 점검하고 PASS/WARN/FAIL과 보고서를 만듭니다. **보기**는 시간 제한·판정·보고서가 없습니다. 보기의 표본은 UE 로그에만 남습니다. 두 모드는 동시에 실행되지 않습니다. 표시 FPS는 렌더 명령 등록 기준이며 실제 모니터·브라우저 전달 FPS와 구분합니다.

목록 JSON을 준비한 경우 Windows에서 다음처럼 자동 보기를 시작할 수 있습니다.

```powershell
.\보기.bat -CctvView '-CctvCheckList=C:\private\channels.json'
```

Linux에서는 `./view.sh -CctvView '-CctvCheckList=/private/channels.json'`을 사용합니다. 최소 JSON 형식은 다음과 같습니다. 인증 정보는 예시에 넣지 않습니다.

```json
{"channels":[{"url":"rtsp://<카메라 주소>/...","transport":"tcp","software_only":false}]}
```

## Pixel Streaming

브라우저 클릭을 사용할 때 `-RenderOffScreen`을 붙이지 마십시오. CCTV-01P 재확인에서 이 인자가 있을 때 버튼 클릭이 반영되지 않는 현상을 확인했습니다.

1. 기존 PixelStreamingInfrastructure의 SignallingWebServer를 먼저 실행합니다. 해당 설치본의 기존 실행 파일과 node_modules를 사용하고, 설정·로그는 저장소 밖으로 지정합니다. 시그널링 HTTP 포트(기본80), 스트리머 WebSocket 포트(기본8888), 필요한 WebRTC UDP 경로를 확인합니다. 포트가 사용 중이면 기존 프로그램을 종료하지 말고 서버 인자로 바꿉니다.
2. Windows는 `PixelStreaming.bat ws://127.0.0.1:8888`, Linux는 `./pixelstreaming.sh ws://127.0.0.1:8888`로 실행합니다. 첫 인자 또는 스크립트 맨 위 기본 주소를 자신의 서버에 맞춥니다. Windows는 뒤에 최대8개의 추가 UE 인자를 받을 수 있습니다. Linux는 뒤의 추가 인자를 그대로 전달합니다.
3. 브라우저에서 서버의 HTTP 주소(예: `http://127.0.0.1/`)에 접속해 재생을 시작합니다. 원격 영상 위에서 마우스·키보드로 주소 입력→추가→보기→중지를 조작합니다. 서버가 다른 PC이면 localhost 대신 해당 서버 주소와 실제 HTTP 포트를 사용합니다.

인코더 기본값과 실행 스크립트는 H.264입니다. `AllowPixelStreamingCommands`는 일반 마우스·키보드 조작에 필요하지 않아 켜지 않습니다. 기본 실행에는 시그널링 URL이 없으므로 로컬 창만 사용합니다. 외부망 ICE/STUN/TURN과 실제 운영 네트워크는 별도로 검증해야 합니다. Linux 화면·Pixel Streaming은 이번 PC에서 검증되지 않았습니다.

## 화면 없는 Linux 점검

```bash
./check-nullrhi.sh /private/channels.json 135
# 시간 제한 없는 디코딩 보기: 운영자가 프로세스를 종료할 때까지 계속합니다.
./view.sh -CctvView -nullrhi -unattended '-CctvCheckList=/private/channels.json'
```

nullrhi에서는 GPU 화면·색·스크린샷을 검증하지 않습니다. 점검은 정상 디코딩이어도 표시 미검증으로 WARN(종료2)을 남길 수 있습니다. 점검 종료 코드는 PASS0/WARN2/FAIL1이며 보고서와 함께 확인합니다. 보기는 보고서·판정 없이 계속 실행됩니다. 자동 재생 입력에는 읽을 수 있는 목록 파일과 쓰기 가능한 Saved/홈 경로가 필요합니다.

## 로그·보고서·계정

기본 Saved 경로는 패키지의 `DTCctvTestHost/Saved`이며 환경에 따라 사용자 저장 경로로 전환될 수 있습니다. 시작 로그의 절대 경로를 확인합니다. UE 로그는 `Saved/Logs`, 점검 보고서는 `Saved/CctvCheck/<시각-PID-ID>/report.md`, `report.json`, `channel-NN.csv`, 가능한 경우 `screenshot.png`입니다. `-abslog=<로그 파일>`과 `-userdir=<전용 사용자 경로>`로 시험별 경로를 지정할 수 있습니다.

주소·계정 입력은 가려지고 주소 저장에는 계정을 제외합니다. 목록 JSON은 인증 정보를 담을 수 있으므로 보호된 위치에 두고 Git·공유 폴더·공개 로그로 보내지 않습니다. 실제 계정이 든 URL을 명령줄에 직접 넣으면 프로세스 목록·셸 이력에 남을 수 있습니다. 계정은 별도 입력이나 보호된 JSON으로 전달합니다.

동봉 FFmpeg의 LGPL 라이선스와 출처는 `ThirdPartyLicenses/FFmpeg/`에 있습니다. 바이너리 이름·SONAME을 임의로 바꾸거나 기존 다른 FFmpeg 플러그인의 파일 위에 덮어쓰지 않습니다.
