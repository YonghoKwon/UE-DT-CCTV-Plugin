# [Claude → Codex] CCTV-01F 역압 대기 결함 수정과 반복 열기 수렴 확인

Claude가 CCTV-01E를 독립 검수한 결과다. 사용자 요청(모든 항목을 만족하도록 원인 파악과 수정)의 연장이다. [CCTV-01C](CCTV-01C.md)의 절대 금지, 다른 작업과의 공존, 직렬 측정 규칙을 그대로 적용한다. 합격 기준을 낮추지 않는다.

## F1. 소비자가 멈춰도 디코딩 스레드가 계속 기다림 (코드 확인, 측정 없음)

`e4a3eb8`의 역압은 `bConsumerCanCatchUp`이 참이면 디코딩 스레드가 프레임마다 최대 750ms를 기다린다. 이 값은 `FDTCctvSession::TakeFrame`이 호출될 때만 갱신된다.

다음 경우 `TakeFrame`이 불리지 않아 마지막 값(참)이 그대로 남는다.

- 게임 스레드 정지(레벨 로딩, GC, 긴 히치). 틱 자체가 없다.
- `UDTCctvStream::RenderLatestFrame`이 `RenderInFlight >= MaxRenderCommandsInFlight`일 때 `TakeFrame` 전에 반환한다(렌더 스레드나 GPU 정체).

그동안 디코딩은 약 1.3fps로 떨어지고, 읽기 스레드는 패킷을 계속 쌓는다. 패킷 큐(120개, 60fps 기준 약 2초)가 넘치면 다음 키프레임까지 건너뛰므로, 정지가 끝난 뒤 화면이 GOP만큼 멈추거나 깨질 수 있다. 수정 전 코드는 이 경우 오래된 디코딩 프레임만 버려 패킷 손실이 없었다. CCTV-01E의 2초 정지 시험은 이 경계 바로 안쪽이라 드러나지 않았을 가능성이 있다. 가설이므로 측정으로 확인한다.

### 재현

현재 코드로 16채널 1080p60에서 하네스 강제 정지를 3초, 5초, 10초로 시험한다. `PacketsDropped`, 재연결, 정지 후 frame age 회복 시간, 키프레임 대기, PNG를 기록한다. 렌더 스레드 정체도 하네스 옵션으로 재현할 수 있으면 함께 시험한다.

### 수정

- 소비자가 최근에 실제로 프레임을 가져갈 때만 디코딩 스레드가 기다리게 한다. 예: 마지막 `TakeFrame` 시각이 최근 일정 시간(예: 100ms 또는 틱 몇 개) 안일 때만 대기를 허용한다.
- `RenderInFlight` 상한으로 건너뛸 때도 소비 여유가 없음을 세션에 알린다.
- 판단 로직은 순수 함수로 분리해 단위 테스트한다(소비자 정지, 렌더 정체, 정상 버스트).

### 합격 기준

| 시험 | 기준 |
|---|---|
| 3초, 5초, 10초 정지 | `PacketsDropped` 0, 재연결 0, 정지 종료 후 2초 안에 frame age 기준 복귀, 정지 후 PNG 정상 |
| 렌더 정체(재현 가능할 때) | 같은 기준 |
| CCTV-01E 지연 조건 4개, 0.3초 버스트, 2초 정지 | CCTV-01E와 같은 기준. 144/30 조건의 대체 0 유지 |

정지 중의 프레임 대체는 불가피하므로 수치만 기록한다.

## F2. Close/Open 메모리 수렴 확인

CCTV-01E 30회에서 Private 기울기는 회당 0.78MiB로 기준(1MiB) 안이지만, 100회면 약 78MiB다. 30회로는 수렴인지 누적인지 구분이 어렵다.

- 16채널 Close/Open을 100회 반복한다. 마지막 30회의 Private 기울기와 10회 단위 평균 추세를 기록한다.
- 합격 기준: 마지막 30회 기울기 회당 0.3MiB 이하, 또는 10회 평균이 마지막 3구간에서 늘지 않음. GPU 메모리와 RHI 텍스처 할당은 늘지 않음.
- 넘으면 할당 위치를 추적해(UE `LLM` 또는 `memreport`, 할당 태그 비교) 원인을 찾고 고친다.
- 핸들과 스레드는 CCTV-01E처럼 원시 총수와 모듈별 집계를 모두 기록한다. 판정 기준은 CCTV-01E E4와 같고, 사용자 결정 전까지 바꾸지 않는다.

### 사용자 결정: Close/Open 핸들·스레드 기준 변경 (2026-11-06)

사용자가 soak에 승인한 스레드 기준을 Close/Open에도 적용하는 것을 승인했다. CCTV-01E의 E4 판정 원칙을 대체한다. 다른 기준(Private, GPU 메모리, RHI 텍스처 할당)은 바꾸지 않는다.

Close/Open은 열 때마다 플러그인 스레드를 새로 만들므로 TID 대신 모듈별 개수로 판정한다. 100회 중 처음 10회는 제외하고, 각 재생 구간 끝 표본으로 다음을 모두 만족해야 PASS다.

- 실행 파일, `ucrtbase`, NVIDIA 모듈(`nvcuda` 등)에서 시작한 스레드 수가 모든 회차에서 같다.
- 스레드 수 변동은 OS 모듈(`ntdll` 등)에서 시작한 스레드에서만 나온다.
- 총 스레드 수와 핸들 수가 늘지 않는다. 마지막 30회의 최댓값이 11~40회의 최댓값을 넘지 않는다.
- 이전 기준의 원시 증감도 함께 기록한다.

CCTV-01E의 30회 결과도 같은 자료로 이 기준에 맞춰 다시 판정해 결과에 함께 적는다.
