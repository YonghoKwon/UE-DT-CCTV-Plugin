# [Claude → Codex] CCTV-01X 외부 공개 RTSP 주소로 연결 점검

사용자 요청: 인터넷에서 쓸 수 있는 공개 RTSP 주소를 찾아, CCTV-01J 연결 점검 도구로 실제 외부 네트워크 연결을 확인한다. 주소 찾기는 Codex가 한다. [CCTV-01C](CCTV-01C.md)의 절대 금지와 공존 규칙을 그대로 적용한다. 코드는 바꾸지 않는다.

## 주소 선택 규칙 (반드시 지킨다)

- **허용:** 운영 주체가 "시험용, 데모용, 공개 스트림"이라고 공식 문서나 페이지에 밝힌 RTSP 주소만 쓴다. 예: 스트리밍 서버나 라이브러리 제작사의 공식 데모, 공개 시험 서비스, 공공 기관이 공개 목적으로 제공하는 스트림.
- **금지:**
  - 보안이 풀린 카메라 목록(Insecam 등), Shodan·Censys 같은 검색 결과, 개인이나 업체의 카메라로 보이는 주소.
  - 출처가 불분명한 블로그나 복사 페이지에만 나오는 주소.
  - 계정 가입, 로그인, 결제가 필요한 서비스, 인증 정보 입력, 약관 동의.
  - 차단 우회.
- 각 후보마다 출처 URL, 운영 주체, 공개 목적 근거를 기록한다. 근거가 없으면 쓰지 않는다.
- 상대 서버에 부담을 주지 않는다. 주소 하나당 동시 연결은 최대 2개, 시험 시간은 연결당 60~120초, 같은 주소 재시도는 3회 이내로 한다.

## 진행

1. 공개 시험용 RTSP 주소를 검색해 후보를 3~6개 고른다. 쓸 수 있는 주소가 하나도 없으면 그 근거(찾은 출처와 쓸 수 없는 이유)를 남기고 끝낸다.
2. 후보마다 기존 도구의 `ffprobe`로 짧게(10초 이내) 연결해 코덱, 해상도, FPS, 전송 방식(TCP/UDP), 대략의 왕복 지연을 확인한다.
3. 응답하는 주소로 01J 점검 도구를 실행한다. Windows 패키지 화면 없는 모드와 Linux 패키지 화면 없는 모드 각각에서, 주소당 1~2채널로 최대 4채널을 점검한다(기본 60초). 결과는 PASS, WARN, FAIL과 원인 문장, 스트림 정보 로그(J0)로 확인한다.
4. 가능하면 같은 주소를 RTSP over TCP와 UDP로 각각 시도한다. 외부 망에서 UDP가 막히는 것은 정상일 수 있으니 원인을 기록한다.
5. 점검 도구의 판정과 원인 문장이 실제 상황과 맞는지 검토한다. 예: 해외 서버의 지연, 저해상도·저FPS 데모, 간헐 끊김.
